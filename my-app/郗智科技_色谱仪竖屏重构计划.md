# 郗智科技 - 色谱仪控制系统竖屏重构计划 (科技工业版)

## 一、 项目背景与设计原则
- **品牌融入**：全面融入**“郗智科技”**的品牌标识，将头部抬头、Logo、默认文案更新为郗智科技的专属元素，彰显企业专业度和品牌力。
- **视觉风格**：**科技工业风 (Tech Industrial)**。采用深邃的控制台暗黑背景，辅以霓虹发光线条（青、橙、激光绿），组件边缘采用金属切割质感，强调仪器的精密感。
- **物理尺寸与布局**：**20cm * 25cm (比例 4:5)** 纯竖屏布局。废弃传统的横向侧边栏，改为“顶部状态舱 + 中部核心操作区 + 底部硬核物理导航栏”的三段式结构。

## 二、 团队角色定义 (Personas)

- **总设计师 (我 - AI)**：负责整体架构把控、全局样式规范的制定、任务拆解与分派、代码审查与最终的整合调度。
- **开发者 A (代号：影刃 - 前端架构与动效专家)**：
  - **人设**：追求极致视觉体验的极客，对 CSS 变量、D3.js 图表、毛玻璃效果及工业风动画（如霓虹频闪、机械按压）有极深造诣。
  - **职责**：负责色彩系统、外壳 Layout、图表暗黑化改造及所有发光/金属质感动效。
- **开发者 B (代号：铁毡 - 业务逻辑与组件重构专家)**：
  - **人设**：稳重严谨的业务骨干，擅长组件的解耦与重构，对 React 状态流转和 Ant Design 组件的深度定制了如指掌。
  - **职责**：负责将原本横向铺开的表单、试管矩阵、数据表格等复杂业务组件，压缩并重构成符合竖屏操作的交互形态。
- **辅助验收人 (您 - 业务代表与最终决策者)**：
  - **职责**：在每个阶段任务完成后进行视觉确认、交互体验验收以及业务逻辑正确性的把关。没有您的确认，绝不进入下一阶段。

## 三、 分阶段执行计划与验收标准

### 阶段一：基建与全局框架重构 (基础设施)
- **任务分派**：
  - **开发者 A**：建立全套 CSS 变量（暗黑基底、荧光高亮）。将 `App.css` 和 `App.js` 中的外壳尺寸限制为 4:5，替换“郗智科技”品牌 Logo 和头部标题。
  - **开发者 B**：将原左侧导航 (`Menu`) 剥离，改造为底部悬浮的“类物理按键”导航栏。调整路由区域的自适应滚动。
- **验收标准**：
  - [ ] 页面整体呈现 4:5 竖屏比例。
  - [ ] 底色变更为深色工业风，顶部清晰展示“郗智科技”字样及全新布局。
  - [ ] 底部三大导航（监控、方法、历史）切换顺畅。

### 阶段二：核心监控视图重构 (Monitor View)
- **任务分派**：
  - **开发者 A**：重绘 D3 实时折线图 (`DynamicLine`)，应用暗黑网格和发光青色线条。设计具有金属质感的系统状态指示灯 (LED)。
  - **开发者 B**：重构试管矩阵 (`buttonTube.js`)，将其改为紧凑型竖向网格布局。将右侧控制面板的按钮改造为真实的“仪表物理按键”排版。
- **验收标准**：
  - [ ] 实时图表在竖向窄屏下比例协调，无样式溢出。
  - [ ] 试管按钮颜色符合暗色环境下的高亮对比度。
  - [ ] 操作按钮点击时有明显的“机械按下”物理反馈。

### 阶段三：方法配置与历史视图重构 (Method & History View)
- **任务分派**：
  - **开发者 A**：将历史页的 Ant Design Table 重写为“竖向卡片流 (Card List)”，每条记录表现为一个独立的数据面板。
  - **开发者 B**：将方法配置 (`method/index.js`) 中的横向表单全部改为上下结构的紧凑排布。洗脱模式等单选/复选框改造成“拨码开关 (Toggle)”样式。
- **验收标准**：
  - [ ] 表单输入框采用无边框或底边发光样式，在竖屏设备上输入体验良好。
  - [ ] 历史记录卡片信息清晰，展开查阅图表详情时不拥挤。

### 阶段四：报警、系统设置与细节打磨 (Polishing)
- **任务分派**：
  - **开发者 A**：重制所有 Modal / Drawer（抽屉）的背景，加入半透明毛玻璃效果。针对“警告 (Warning)”加入红色霓虹频闪边框动效。
  - **开发者 B**：重构悬浮按钮 (FloatButton)，将其贴合屏幕边缘或集成到控制舱侧边。优化 Socket 状态推送时的 UI 刷新性能。
- **验收标准**：
  - [ ] 报警弹窗具有强烈的工业警告感。
  - [ ] 整体系统无横向滚动条，细节无死角，达到交付标准。

## 四、 工作流约定
1. 总设计师向辅助验收人（您）确认当前阶段计划。
2. 确认无误后，调度 A 和 B 进行代码修改。
3. 修改完毕后，提供结果汇报并请您验收。
4. 验收通过，开启下一阶段。
